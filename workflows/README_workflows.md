- 작업 절차가 불명확할 때

## 2. 텍스트 호흡 예측 엔진 (Reading Pace Prediction Engine)

각 문단/문장 블록의 예상 소화 시간을 계산하고, 이에 따라 시각 출력과 TTS 타이밍을 조정한다.

### 2.1 목적

"사용자가 이 문장을 정확히 몇 초 만에 읽는가"를 맞히는 것이 아니라,
**사용자에게 더 잘 맞는 출력 리듬을 추정**하는 것이 목적이다.

### 2.2 부호 기반 가중치 (Punctuation Weights)

| 부호 | 변수 | 역할 |
|---|---|---|
| 마침표 `.` | `w_dot` | 문장 종결 — 표준 정지 |
| 쉼표 `,` | `w_comma` | 부분 정지 — 짧은 호흡 |
| 물음표 `?` | `w_quest` | 의문 — 약간의 긴장 유지 |
| 느낌표 `!` | `w_excl` | 강조 — 빠른 전달, 짧은 딜레이 |
| 물결표 `~` | `w_tilde` | 여운 — 부드러운 호흡 연장 |
| 생략부호 `…` | `w_elli` | 침묵/여운 — 최대 딜레이 |

### 2.3 구조 기반 가중치 (Structure Weights)

| 구조 | 변수 | 역할 |
|---|---|---|
| 큰따옴표 `"..."` | `w_dquote` | 대사 블록 — 발화 리듬 조정 |
| 작은따옴표 `'...'` | `w_squote` | 내면 독백 — 내향적 리듬 |
| 공백 ` ` | `w_space` | 단어 간 미세 딜레이 |
| 들여쓰기 | `w_indent` | 단락 시작 — 짧은 준비 딜레이 |
| 1회 줄바꿈 | `w_newline1` | 문단 내 전환 |
| 다중 줄바꿈 | `w_newlineN` | 장면 전환 — 긴 정적 |

### 2.4 인지 부하 보정치 (Cognitive Load)

아래 요소가 많을수록 출력 리듬을 느리게 조정한다.

- 현재 화의 등장인물 수
- 대명사 빈도 (지시 대상 추적 부하)
- 장면 전환 횟수
- 문장 길이 분산 (불규칙할수록 인지 부하 증가)
- 세계관 고유명사 밀도

## 3. Director Mode 처리 절차

사용자의 중간 개입은 FlowScribe의 핵심 기능이다.
Director Mode는 **최상위 우선순위(L0)**를 갖지만, 서사를 무조건 파괴하지 않는다.

### 3.1 입력 예시
- "이 캐릭터를 더 차갑게 바꿔줘"
- "이번부터 분위기를 더 어둡게"
- "복선을 줄이고 감정선을 늘려줘"
- "주인공 말투를 더 담백하게 해줘"

### 3.2 처리 순서

**Step 1: 지시 분류**
입력된 Director 지시를 다음 유형으로 분류한다.
- `캐릭터 속성 변경` — 성격, 말투, 행동 패턴
- `분위기/톤 변경` — 전체 서사 무드
- `구조 변경` — 복선 빈도, 감정선 비중, 갈등 강도
- `스타일 변경` — 문체, 문장 길이, 서술 방식

**Step 2: 세계관 충돌 검사**
`story_data/README_story_data.md`의 World Bible을 참조하여 지시가 핵심 세계관 규칙을 파괴하는지 확인한다.

규칙:
- 핵심 세계관 규칙(`world_rules`)을 위반하는 지시는 **즉시 적용하지 않는다.**
- 대신 사용자에게 충돌 사실을 알리고, 세계관 안에서 최대한 반영 가능한 대안을 제시한다.

**Step 3: 복선 재맥락화 판단**
기존 복선(Foreshadow Memory)과 충돌하는 지시가 있을 경우:
- 복선 **삭제보다 재맥락화를 우선**한다.
- 예: "악당을 제거해줘" → 악당을 삭제하는 대신 복선을 재해석하는 방향으로 반영.

**Step 4: 적용 시점 결정**

| 지시 유형 | 적용 시점 |
|---|---|
| 즉시 반영 가능한 스타일/톤 변경 | 다음 화 첫 문단부터 |
| 캐릭터 속성 변경 | 다음 화부터 점진 적용 |
| 장기 구조 수정 (플롯 방향 등) | 2~3화에 걸쳐 점진적 반영 |

**Step 5: Director Override 기록**
적용된 지시는 `story_data/`의 `director_overrides` 로그에 반드시 기록한다.

```json
{
  "timestamp": "ISO8601",
  "instruction": "원문 지시 텍스트",
  "type": "character | tone | structure | style",
  "applied_from_episode": 0,
  "gradual": true,
  "world_conflict": false,
  "recontextualized_foreshadow": false,
  "notes": "적용 시 특이사항"
}
```

### 3.3 핵심 원칙 요약
1. 세계관 핵심 규칙은 유지한다.
2. 복선은 삭제보다 재맥락화를 우선한다.
3. 즉시 반영 가능한 항목은 다음 화부터 적용한다.
4. 장기 구조 수정은 점진적으로 반영한다.

## 4. Visual Pacing Engine

문장부호, 줄바꿈, 긴장감에 따라 **시각적 출력 템포**를 동적으로 제어한다.
목적은 단순 애니메이션이 아니라 **텍스트가 장면처럼 느껴지게 만드는 연출**이다.

### 4.1 부호 → 딜레이 매핑

| 트리거 | 시각 효과 | 딜레이 |
|---|---|---|
| `…` (생략부호) | 페이드 지연 + 출력 정지 | 최대 (600~1200ms) |
| `!` (느낌표) | 짧은 진동 또는 강한 전환 | 짧음 (100~200ms) |
| 다중 줄바꿈 | 정적 연출 강화 | 중간~길게 (400~800ms) |
| 빠른 대사 연속 | 출력 속도 증가 | 딜레이 최소화 |
| 심리 묘사 구간 | 단어 간 호흡 증가 | 단어 단위 미세 딜레이 |

### 4.2 긴장감 기반 조정

긴장감이 높은 구간 (Urgency 신호 높음):
- 출력 속도 증가
- 딜레이 단축
- 시각 효과 강도 증가

긴장감이 낮은 구간 (감성/서정 장면):
- 출력 속도 감소
- 딜레이 연장
- 페이드 등 부드러운 전환

## 5. MVP 실행 순서 (Phase 1~4)

### Phase 1 — 기본 파이프라인 구축
- 텍스트 생성 (DeepSeek-V3.2 연동)
- 회차 저장
- 기본 Reader Profile 구축 (static + dynamic 초기화)
- 문장 호흡 기반 Visual Pacing 구현
- 행동 로그 수집 시작

### Phase 2 — 감정·연출 레이어 추가
- TTS 감정 반영 (emotion tag → voice parameter 매핑)
- SessionPacing 실시간 조정
- Director Mode 처리 절차 적용
- 장르별 GenreProfile 누적 시작

### Phase 3 — 오디오 생태계 통합
- BGM 자동 매칭 (장면 태그 기반 벡터 검색)
- Spatial Audio 처리
- Voice Archive 연동
- Foreshadow Memory 장기 플롯 분기 고도화

### Phase 4 — 음성 생태계 확장
- 내부 음성 튜닝 시스템 고도화
- Voice Archive 공유 생태계 확장
- 사용자 제작 음성 페르소나 추천 기능
- 캐릭터별 보이스 스타일 자동 매핑

각 Phase는 이전 Phase가 안정화된 후 다음으로 넘어간다.
