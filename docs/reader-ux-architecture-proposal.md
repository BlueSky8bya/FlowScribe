# Reader UX Architecture Proposal — Phase 4.20

> 본 문서는 reader 화면 구조의 현재 상태 평가 + 대안 비교 + 최종 추천이다.
> Phase 4.19에서 사이드바 minimal + ep-end cards detailed로 분리한 결정의 타당성을 재검토한다.

---

## 1. 현재 구조 (Phase 4.19 기준)

```
┌─────────────────────────────────────────────────────────────────┐
│ [좌] 책 목록  │ [중] 본문 영역                  │ [우] 우측 패널 │
│              │                                  │                │
│ - 책 카드     │ - output (SSE 스트리밍)         │ 인물 정보:      │
│ - 회차 목록   │ - 본문 단락                     │  - 이름 + 성별  │
│              │                                  │     (minimal)   │
│              │ - 본문 하단                     │                │
│              │   ┌─────────────────────────┐   │ 낭독 가이드     │
│              │   │ Episode End Cards        │   │ (모드별)        │
│              │   │ - 인물 카드 (detailed)   │   │                │
│              │   │   확장/축소              │   │ 독자 프로필     │
│              │   │   소지품 카드 포함       │   │                │
│              │   └─────────────────────────┘   │ 디버그 패널     │
│              │ - 작가 개입 / regen / 캡처+ 등  │                │
└─────────────────────────────────────────────────────────────────┘
```

**Phase 4.19 변경:**
- 우측 패널의 인물 정보를 detailed → **minimal (이름 + 성별 색)**
- 본문 hover: 감정/신체 tooltip 제거 → **성별별 정적 밑줄만**
- 본문 하단에 Episode End Cards 신규 — 회차 종료 시점 detailed 인물 카드 (확장/축소)
- placeholder UX: token 첫 도착 시 "정리 중" spinner 표시 (Phase 4.19C)

## 2. 평가 기준

| 기준 | 우선순위 |
|---|---|
| 독자 몰입 | 高 |
| 스포일러 방지 | 高 |
| 상태 동기화 난이도 | 中 |
| 기술 구현 난이도 | 中 |
| 오류 발생 가능성 | 高 |
| 캡처+ 와의 일관성 | 中 |
| 모바일/데스크톱 UX | 中 |

---

## 3. 현재 구조의 장점

| 장점 | 설명 |
|---|---|
| 본문 중간 정보 노출 차단 | hover/사이드바에 미래 회차 감정/소지품이 안 보여 스포일러 방지 |
| 회차 종료 후 정보 자연스러움 | ep-end cards는 "다 읽고 확인" 시점에 노출되어 흐름 방해 없음 |
| detailed/minimal 분리 | 사이드바는 빠른 식별, ep-end는 깊이 있는 상태 |
| 단일 helper(`_buildSceneCharDetailedCardHtml`)로 사이드바·ep-end 공유 | 마크업 일관성 |

---

## 4. 현재 구조의 위험

| 위험 | 영향 | 발생 가능성 |
|---|---|---|
| ep-end cards가 본문 하단에 위치 → 모바일에서 스크롤 끝까지 가야 보임 | 인물 상태 확인 불편 | 中 |
| 사이드바 minimal — 신체 부상/무력 상태 같은 "독서 중 알아야 하는 정보"도 사라짐 | 인물 상태 추적 못 함 | 中 |
| char-states 도착 지연 시 placeholder가 길게 보임 (현재 batch 구조) | 체감 지연 | 高 (R5 streaming 후 완화) |
| capture+(인물 정보 포함 캡처)는 사이드바 데이터 vs ep-end cards 어느 source? | 혼동 | 中 |
| regen 시 이전 ep cards가 잠시 남을 수 있음 → Phase 4.19C에서 _clearDebugPanels로 hide | 중복 노출 | 低 (이미 fix) |
| ep-end cards가 detailed → 모바일 1열에서 화면 길이 폭증 | 스크롤 부담 | 中 |

## 5. 대안 구조

### 대안 A — **현재 (Phase 4.19)** 유지 + 미세 보정

```
사이드바 minimal (이름+성별)
본문 하단 ep-end cards detailed
```

보정:
- 사이드바에 "신체 부상/무력" 같은 시각 신호만 추가 (감정 미노출)
- ep-end cards 모바일 1열 압축 (확장 시만 detailed)
- placeholder 지연 시 시간 안내 ("약 5초")

장점: 기존 결정 유지, 변경 최소
단점: 모바일 길이, 사이드바 정보 부족 그대로

---

### 대안 B — **사이드바 medium**

```
사이드바: 이름 + 성별 + 신체 상태 아이콘 (부상/탈진/정상)
본문 하단 ep-end cards detailed (감정/위치/소지품 등)
```

장점:
- 신체 부상은 독서 중 알아야 함 — 사이드바에 두면 자연스러움
- 감정/관계는 ep-end에서만 → 스포일러 차단 유지

단점:
- 부상 정보도 사실 회차 종료 시점 기반이라 본문 중간에 노출은 작은 스포일러

---

### 대안 C — **사이드바 + 본문 하단 + 사이드바 토글**

```
사이드바: 이름 + 성별 (default)
사이드바 토글 [▾ 상세] 클릭 → ep-end card 동등 표시
본문 하단 ep-end cards detailed (변경 없음)
```

장점:
- 사용자 선택권 — 빠른 확인은 사이드바 토글, 깊은 정보는 ep-end
- 모바일에서도 사이드바를 접고 ep-end만

단점:
- 토글 상태 관리 + 캡처+ 일관성 문제 복잡
- 동일 데이터의 두 표현 유지

---

### 대안 D — **사이드바 제거 + ep-end만**

```
인물 정보 영역 = 본문 하단 ep-end cards만
사이드바는 낭독 가이드/독자 프로필/TTS 컨트롤만
```

장점:
- 단일 source — 혼동 없음
- 본문 영역이 넓어짐 (본문 폭 제한 760px → 1000px+ 가능)

단점:
- 본문 중간에 인물 식별 단서가 hover/밑줄뿐 → 본 회차에서 처음 등장 인물 구분 어려움
- 모바일 친화적이지만 데스크톱 UX 손실

---

## 6. 최종 추천

**대안 B (사이드바 medium) 채택. 단, 단계적.**

### 6.1 R7.0 — 현재 유지 + 모바일 보정

- 사이드바 minimal 유지 (이름+성별)
- ep-end cards 모바일 1열 압축 (collapsed default, 클릭으로 펼침)
- placeholder 시간 안내 (LLM 평균 대기 5-15초 표기)

### 6.2 R7.1 — 사이드바에 신체 부상 신호만 추가

- `_currentCharStates`에서 physical_state만 사이드바에 노출
- "부상"·"탈진"·"무력" 단어 매칭 → 작은 빨간 점 표시
- 감정/관계/역할/소지품은 사이드바에 노출 안 함

### 6.3 R7.2 — capture+ source 통일

- capture+가 ep-end cards markup을 직접 캡처 (사이드바와 별도 source 제거)
- 캡처 결과 = 사용자가 본 ep-end cards와 동일

### 6.4 R7.3 — placeholder 단계화

R5 (streaming) 적용 후:
- 본문 token 도착 시작 → placeholder "이번 화의 인물 상태를 정리하고 있습니다..."
- 본문 token 끝 + state 도착 → 카드 교체
- state 지연 시 (>10s) "잠시 더 기다려주세요" 보강 안내

---

## 7. 모바일 vs 데스크톱

### 모바일 (~ 560px)

```
[본문]
  ...본문...
[작가 개입 / regen / 캡처]
[Episode End Cards — 1열, collapsed default]
[하단 네비게이션]
```

사이드바는 햄버거 메뉴 또는 별도 화면.

### 태블릿 (560-960px)

```
[책 목록 narrow] | [본문] | (사이드바 숨김)
                  본문 하단 ep-end 2열
```

### 데스크톱 (960+)

현재 3단 레이아웃 + ep-end 2-3열 grid.

---

## 8. 캡처+ 일관성

현재 `exportToClipboard(withChars=true)`가 사이드바와 별도로 캡처용 인물 카드를 그린다 ([generate.js:1722-1863](../public/js/generate.js#L1722)). 이를 ep-end cards markup으로 통일:

```
captureEpisode(withChars=true)
  ├─ 본문 markup
  └─ ep-end cards 영역 markup (그대로 캡처)
```

장점: 사용자가 화면에서 본 카드 = 캡처에서 본 카드. 일관성 향상.

## 9. spec 준수

- "독자 몰입 / 재생성 다양성 / 사용자 직접 만든 세계관 존중 / 빠른 체감 속도 / 명확한 상태 구조" 5축 중 reader UX는 (1) 독자 몰입, (5) 명확한 상태 구조에 직접 영향.
- 대안 B는 두 축 모두 만족하면서 변경 최소.
